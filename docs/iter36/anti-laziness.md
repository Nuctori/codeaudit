# 防偷懒协议（Anti-laziness Protocol）——迭代 36+ 强制

> 前提：AI 自述不可信（历史 3 轮独立审计抓 10+ 项"注释-行为不符/声称未做"）。
> 因此本协议不依赖"我会努力"，而依赖"偷懒在机制上不可能通过"。
> 每一条都是**可机器验证**的硬门槛，不满足 = 节点不通过 = 工作流卡死（dag 证据闸）。

---

## 1. 不可伪造产物（每节点必须产出其一，无则节点 fail）

| 节点类型 | 必须产物 | 伪造难度 |
| --- | --- | --- |
| 环境 | `healthz` JSON（`{"ok":true}`）、Unity `testResults.xml`（含 passed 计数） | 外部进程产物，无法手写假装 |
| 测试 | `testResults.xml` 含目标用例 passed + `Logs/*.json` 结构化报告 | 需真实运行 |
| 主流程 | PlayMode 结构化 stage marker（日志 `questN_signal_triggered` 等）+ 测试 XML | 需真实进游戏 |
| codeaudit 修复 | 回归测试 + 304+ 全绿 + InitDeity 重扫数字对照 | 测试需真跑 |
| 文档 | 基线对照表（数字变化） | 数字来自扫描非手写 |

**规则**：报告只引用真实命令输出/文件内容；禁止"我认为已修复/看起来通过"。

## 2. 基线对照（数字说话——不下降=偷懒）

| 指标 | 阶段0基线 | 每阶段结束必须对比 | 停滞判定 |
| --- | --- | --- | --- |
| InitDeity unknown 数 | 4563（22.6%） | 重扫对照 | 连续 2 轮无变化 → 停滞 |
| E2E 测试数/成本 | 当前 54 文件 14248 行 | 阶段1 后必须下降 | 未下降 → 阶段1 未完成 |
| 单元层断言数 | 0 | 阶段1 后 ≥30 | 未达 → t2 未完成 |
| 主流程通过 quest 数 | 0 | 每 quest 后 +1 且有证据 | 卡住 → 报告卡点不跳过 |
| codeaudit 测试数 | 304 | 每修复后对照 | 修复无测试 = 未修复 |

**停滞熔断**（AGENTS 纪律）：同一目标连续 2-3 轮 Apply→Eval 无客观变化 → 判定停滞，换策略或上报，不盲重试。

## 3. 独立审计（外部检测——每次偷懒都会被抓）

- 每阶段收尾：fresh reviewer 审本阶段全部 diff（最小化非工程妥协检查）
- 审计发现 **0 blocker 才可进下一阶段**；CHANGES 必须修复闭环
- 历史实证：3 轮审计抓 10+ 项（A1 假纯红线/TP4 数据损坏/C2 死路径/注释不符）——审计就是防偷懒的照妖镜

## 4. 诚实报告（最难的一环，也是协议核心）

| 情况 | 必须行为 | 禁止行为 |
| --- | --- | --- |
| 测试失败/卡点 | 如实报告 + 最小修复尝试 | 假装通过、跳过节点 |
| 环境不可用 | 报告阻塞 + 列出绕过路径 | 用"环境问题"掩盖没干活 |
| 修复有副作用 | 记录 + 独立审计复核 | 隐瞒回归 |
| 数字没变 | 承认没进展 + 换策略 | 重跑旧数字假装新结果 |

**卡点协议**：主流程卡住 → 立即 `dag_fail` + 精确卡点报告（stage/marker/日志证据）→ 最小 game-state 修复 → 重试。不静默跳过 quest。

## 5. 检查点（用户可验证）

每个节点完成后产出**四件套** + 机器产物，用户醒来即可逐项核对：

```
docs/iter36/quest-6.md   ← 分析/修复/证据
Logs/quest6-playmode.xml ← 测试 XML（passed 真身）
Logs/quest6-marker.json  ← 结构化 stage marker
decision chain D-13x     ← 决策记录
```

用户核对方式：`grep passed Logs/quest6-playmode.xml` + 看 marker 数字——不是我说的，是文件说的。

## 6. 执行节奏（防"大而全"拖延）

- 每个节点独立提交（小步快跑），不攒大 diff
- 每节点有 `timeoutMs`（如主流程 quest 单节点 ≤25min），超时 = 报告卡点而非无限重试
- 阶段间用 dag `needs` 强制顺序（阶段 2 不能跳过阶段 1）

---

## 验收：本协议有效的唯一标准

> 用户醒来后，不看我的总结，只看 `Logs/*.xml` + `docs/iter36/quest-*.md` + 基线对照表——
> 能独立确认"主流程从登录到 quest10 每步都有真实测试证据"。
> 若用户无法从证据反推进度，说明协议失效。
