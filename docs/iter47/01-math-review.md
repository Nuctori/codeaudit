## 一、类 chunk 的 MCCabe（方法之和）：合法度量还是噪声？

### 1.1 数学定性：不是"非法"，是**量纲错配**

MCCabe 的定义对象是**单入口单出口**的流程图的 v(G) = e − n + 2p。类的自然图 = 方法流程图的**不交并**，其圈数恰为 Σ vᵢ。所以「方法之和」是一个良定义的图不变量——数学上不非法。但：

1. **类有 k 个入口，不是一条路径空间**。v(不交并) 混合了 k 个互不相干的路径空间；它不回答「类的任何可执行路径有多复杂」（该类问题无定义），只回答「k 个图加起来有多大」。
2. **Σ 与 k 共线**：C_class = ΣCᵢ − k + 1 ≈ k·(ā−1)。ā 变化小（2-5 常见），k 变化大（1-1000+）。所以类级 C 的实际排序力 ≈ **按方法数排序** = 尺寸代理。计划实证（C=1136/797 全是大类/生成类）正是这个共线性的直接表现。
3. **非单射（决策信息擦除）**：(k=2, ā=50) 与 (k=50, ā=2) 的 Σ 都是 ≈100，但重构策略相反（前者拆 god method，后者无事可做）。单数把分布形态（唯一决策相关部分）压缩掉了。
4. **与自身标准不一致**：F2 证明 --complexity 已按函数级标准执行；--modules 的 max 对**异质总体**（函数级 C 与类级 Σ 混取 max）取极值——max 的定义要求同量纲输入，Σ 与 C 不同量纲，**维度混排**是形式错误，比"用了非标准度量"更本质。

**结论**：类 chunk 的 C 应从聚合中剔除（理由：尺寸代理 + 量纲混排 + 非单射），但不必删除字段（JSON 是 D-065 库发布定位的公共数据工件；保留但须文档化语义「Σ 方法复杂度——尺寸代理，非复杂度」）。

### 1.2 类级复杂度画像的正确形态：分布，不是单数

类级画像 = 方法复杂度分布，最小充分统计量三件：(k, M, p90)：

- **k（方法数）**：尺寸上下文（Σ 已证明共线于 k，k 自己更诚实）。
- **M = max Cᵢ**：分诊值（"最复杂的那个方法是谁"——重构优先目标）。
- **p90**：尾部质量——区分「一个 god method + 一堆 trivial」（p90 ≪ M）与「整体缠结」（p90 ≈ M）。

**分布比单数信息量大多少**：单数 Σ 的信息量 ≈ log 值域（几十比特），但形态信息（偏度）为 0；三元组 (k, M, p90) 的边际增益**恰是形态**——而形态是唯一决策相关部分（拆方法 vs 拆类）。严格说 (k, M) 已可区分两种重构策略；p90 是第三位、为尾部稳健性；**avg 冗余**（右偏分布下 avg 被 M 支配，且 avg = Σ/k 继承尺寸共线性）——按极小性**不引入 avg**。

**实现可行性**：方法→类归属可从限定名恢复（link.ts:489 `name = "${ownerClass}.${name}"`），但嵌套类（`Outer.Inner.M`）脆弱；正确做法是消费侧重建 owner（或未来在 Chunk 补 ownerClass——本轮不动类型）。分布一律**从基准函数集现算**（verdicts 全量在手），禁止从类聚合反推（见 §3 不可组合性）。

## 二、用户说的「嵌套深度」：nesting 与 MCCabe 的正交性

### 2.1 数学关系：互不决定，只有单向弱不等式

- C = |D| + 1（D = 决策节点集，pack 表驱动）；n = 结构嵌套最大深度。
- **n ↛ C**：C# nestingNodes 含 method/lambda/class（非决策节点）——空 lambda 套空 lambda，n=2 而 C=1。结构折叠不产生决策。
- **C ↛ n**：20 个平铺 elif（C=21, n=1）vs 5 层嵌套 if（C=6, n=5）——同一 C 下 n 可差一个量级。switch/case/三元/catch 入 complexityNodes 而不入 nestingNodes（csharp.ts:929-940 vs 771-784），更强化了两轴分离。
- 唯一关系：每个嵌套层至少由一个决策节点引入 ⇒ n 的决策部分 ≤ |D| = C−1；但 C# 结构节点（lambda/method）使 n 可越过此界。即 **(C, n) 的可行域是无约束的平行四边形区域**，任何一轴都不能确定另一轴。

**正交性裁定：成立**。两轴独立承载不同重构语义：C 回答「有多少分支」（宽/密度），n 回答「折得多深」（折叠度）；「平铺但密集」与「窄而深」是两种不同的重构操作（提取 vs 展平），单列任一轴都会擦除另一轴的信号。

### 2.2 组合模型 f(C, n) 值不值得引入：不值得（现状）

- 任何 f(C,n) 都是二元组的**有损投影**：f(c₁,n₁) = f(c₂,n₂) 可对应不同 (c,n)——组合数擦除的恰是 §2.1 的正交信息。
- 认知负荷确实同时依赖两轴（Campbell 认知复杂度即对嵌套加权的 Σ——这是唯一有理论根基的组合形态），但：
  - 仓库自有公理5（F8）明令「不存在拍脑袋的加权求和」——自造 C×n 或 αC+βn 违反项目文档化哲学；
  - 组合指标的分诊决策规则（如 C×n > t）等价于 (C,n) 平面上的曲线边界，而双列 + 双阈值（C > 15 ∨ n > 5）是矩形边界——对"是否标记"用途，双阈值覆盖一切合理阈值下的组合规则；差异场景（低 C 高 n）恰是双列展示让人眼直接看到的。
- **裁决：保持正交双列输出，不计算不存储组合指标。** 若未来真有消费者需要认知权重语义，正解是**整体替换**为 Campbell（含阈值重标定），不是新增组合字段——记为 do-later，触发条件 = 出现需要认知权重语义的消费者。

## 三、簇聚合层级（函数→类→模块）的数学结构

### 3.1 每层指标

| 层 | 指标 | 语义 |
| ---- | ------ | ------ |
| 函数 | C（MCCabe）、n（nesting） | 基准单元，标准函数级度量 |
| 类 | (k, M, p90)（方法分布） | 分诊三元组（§1.2），**不用** Σ |
| 模块 | max（函数级 C）为主 + 可选 p90 | 最坏点 + 尾部，从基准集现算 |

### 3.2 单调性/可组合性：max 是层级唯一可组合的单数

- **max**：幂等、交换、结合（join 半格）⇒ 模块 max = max(全体函数 C) = max(各类 max)——**划分无关**：把模块拆成任意子模块，各部分 max 只降不升，并集 max 不变。最坏点复杂度天然层级化。
- **Σ**：也可加（Σ_模块 = Σ_类），但语义 = 尺寸（§1.1），代数可组合 ≠ 语义可用。
- **分位数（p90）不可组合**：p90(并) ≠ f(p90(各部件))——必须逐层从基准函数集现算。好消息：verdicts 含全部函数 chunk，任何层的分布都可直接算。**设计规则：p90 是纯报告统计，永远从基准数据计算，禁止从类聚合推导**。
- **当前实现的精确形式缺陷**：moduleSummary 的 max 对**异质总体**取极值——函数（C 量纲）+ 类（Σ 量纲）混排。max 的定义域是同一统计量的样本集；混排后的"max"不落在任何单一量纲上，不可解释。这就是污染的形式化表述（比"非标准"更硬：**量纲错误**）。

## 四、复杂度模型的极小性：MCCabe 近似 vs 标准 vs Campbell

### 4.1 当前实现与标准 MCCabe 的偏差清单（已核实）

| 偏差 | 方向 | 严重度 |
| ------ | ------ | -------- |
| 非短路布尔运算符（==、!=、<、! 等）不计数（extended MCCabe 计） | 低估条件密度 | 低（排名用途；`if (a && b)` 的 && 已计，偏差仅在裸比较符） |
| C# switch：`switch_statement` +1 且每 `case_pattern_switch_label` +1（标准只计 case，switch 本身不计） | 每个 switch 高估 1 | 可忽略（每构造常数偏移，排名序不变） |
| 缺失形态：C# `switch_expression`（C# 8+）、Python `match_statement`/`case_clause`（3.10+）、TS `??=`/`&&=` | 低估现代语言形态 | 中（pack 表补全一行项，见 §5.3） |
| nesting 不加权（那是 Campbell 不是 McCabe） | — | 非偏差，是模型边界 |

### 4.2 偏差可接受性：可接受，且是极小形态

- C 的消费面（F7）：仅 --complexity 排名列表 + --modules max（修后）。**无证明义务**（A6/S4 不挂载展示度量）——与 purity 的健全性约束是两类对象。排名用途下，关键性质是：近似对**已纳入的构造集**单调、跨语言表驱动一致、阈值是启发锚点（绝对标定不构成正确性问题）。
- 极小性论证：表驱动 + 共享一次遍历是计数的最简形态；计非短路运算符会与节点计数双算纠缠（`if (a == b && c)` 的精确归属争议），收益（更贴近教科书数字）无消费侧（排名序几乎不变）。
- **Campbell 认知复杂度：拒绝 do-now**。理由：换指标 = 全量数字重标 + 阈值重标 + 无消费者；且 Campbell 的嵌套加权是**有观点**的权重（每嵌套层 +1 的合理性是设计选择非定理），项目公理5 反对拍脑袋权重。触发条件见 §2.2。
